# Board Export UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make quick visual exports follow the board view the user is looking at and redesign the export modal around a polished, live, expandable preview on the right.

**Architecture:** Keep `BoardExportDocument` as the shared renderer for PDF/PNG and pass the active view explicitly from the board into both export entry points. Add a small typed resolver for the selected format, scope, layout, and theme, then use it to keep the modal preview and download configuration in sync. Keep CSV/Excel as data exports with a sheet-style preview; layout and color theme apply only to PDF/PNG.

**Tech Stack:** Next.js App Router, React, strict TypeScript, Tailwind CSS, existing board export components and Vitest.

**Spec:** User request in this task; existing export behavior in `src/components/kanban/board-export-modal.tsx` and `src/components/kanban/board-export-document.tsx`; project design and theme requirements in `docs/design.md`, `docs/theme-system.md`, and `AGENTS.md`.

## Global Constraints

- Use strict TypeScript and keep export selection parsing explicit.
- Use semantic theme tokens for interface controls; reserve fixed colors for intentional export artwork.
- Preserve the retro lofi indigo direction and review both light and dark themes.
- Keep direct exports available from the board menu and ensure the menu communicates the active view and filtered item count.
- Do not add a UI testing dependency; use the existing Vitest setup for pure export behavior and manual browser verification for layout and interaction.
- Update `docs/system-guide.md`, `src/components/help/help-center-client.tsx`, `docs/theme-system.md`, and a dated `docs/agent-notes/` note for the changed export workflow.
- Before completion, run `npm run lint`, `npm run build`, `npx prisma validate`, and focused export tests.

### Task 1: Define and test export selection rules

**Files:**
- Create: `src/lib/kanban/export-config.ts`
- Create: `src/lib/kanban/export-config.test.ts`
- Reference: `src/components/kanban/board-export-modal.tsx`

**Interfaces:**
- `ExportView = "kanban" | "table"`
- `ExportFormat = "pdf" | "png" | "excel" | "csv"`
- `ExportScope = "all" | "filtered"`
- `resolveExportSelection(input)` accepts `format`, `currentView`, optional `selectedLayout`, `scope`, and `theme`; for PDF/PNG it returns `{ kind: "visual", format, layout, scope, theme }`, while Excel/CSV return `{ kind: "data", format, scope }`.
- A visual export uses `selectedLayout` when supplied and otherwise uses `currentView`. A data export has no layout or theme fields, preventing irrelevant modal options from leaking into its configuration.

- [ ] **Step 1: Write failing resolver tests**

In `src/lib/kanban/export-config.test.ts`, cover these concrete cases:

```ts
expect(resolveExportSelection({
  format: "pdf", currentView: "table", scope: "filtered", theme: "dark",
})).toEqual({
  kind: "visual", format: "pdf", layout: "table", scope: "filtered", theme: "dark",
});

expect(resolveExportSelection({
  format: "png", currentView: "table", selectedLayout: "kanban", scope: "all", theme: "light",
})).toEqual({
  kind: "visual", format: "png", layout: "kanban", scope: "all", theme: "light",
});

expect(resolveExportSelection({
  format: "csv", currentView: "kanban", scope: "filtered", theme: "dark",
})).toEqual({ kind: "data", format: "csv", scope: "filtered" });
```

Expected: FAIL because `export-config.ts` has not been created.

- [ ] **Step 3: Implement the typed resolver**

Add the exported unions and discriminated result types described above. Keep the function pure: visual formats resolve layout from `selectedLayout ?? currentView`; data formats return only format and scope.

- [ ] **Step 4: Run the focused tests**

### Task 3: Put a live, interactive preview beside the export controls

**Files:**
- Modify: `src/components/kanban/board-export-modal.tsx`
- Modify: `src/components/kanban/board-export-document.tsx` only if a small presentation prop is needed to reuse the existing renderer safely
- Test: `src/lib/kanban/export-config.test.ts`
- Reference: existing modal primitives in `src/components/ui/`

**Interfaces:**
- Keep preview state in `BoardExportModal`: selected format, scope, layout, theme, preview zoom, and expanded state.
- Selected PDF/PNG uses `BoardExportDocument` with the resolved selection and current columns. Selected Excel/CSV uses a read-only sheet-style sample from the exact prepared export rows.
- Preview controls expose accessible names for zoom in, zoom out, fit/reset, expand, and restore. The existing download handlers receive the same resolved selection shown in the preview.

- [ ] **Step 1: Set the modal layout and interaction contract**

Use a wide two-pane dialog on desktop: export settings and format selection on the left, a sticky live preview panel on the right. Keep the modal within the viewport with a bounded height and scroll the controls and preview independently. On narrow screens, stack the panes and keep the primary export action reachable.

- [ ] **Step 2: Make format selection drive relevant controls and preview**

Keep PDF, PNG, Excel, and CSV selectable in the left pane. For PDF/PNG, show scope, layout, and theme controls. For Excel/CSV, hide layout and theme and show a sheet-style preview of the selected rows. Add one clear primary download button for the selected format; keep the existing one-click quick-export menu separate.

- [ ] **Step 3: Synchronize the preview with current options**

Render the visual preview using the resolved scope, layout, and theme whenever any of those selections changes. Use the same prepared rows and column metadata as the download path for the data preview. Add an empty state when the selected scope contains no cards.

- [ ] **Step 4: Add expand, zoom, and scrolling behavior**

Add an expand/restore control that widens the same dialog to a near-full-screen view without opening a nested modal. Add zoom-in, zoom-out, and fit/reset controls with a bounded zoom range. Keep wide table previews horizontally scrollable and tall previews vertically scrollable; ensure preview controls stay visible while the preview content scrolls.

- [ ] **Step 5: Verify keyboard and responsive behavior in the running app**

Check dialog close with Escape, focus visibility, focus return to the launch button, and `aria-label` values for preview controls. Inspect desktop `1440×900` and mobile `390×844` in light and dark themes. Confirm expand/restore, zoom, both scroll axes, selected format, scope, layout, and theme update the visible preview.
